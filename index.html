Name

mars — a coding agent with the IDE wired in

Language servers on every write, real debuggers over DAP, and a Rust core that keeps search and the shell inside the process. One binary, no WSL bridge.

Synopsis

mars [--model name] [--cwd dir] [message] · also via npm, Bun, Nix and mise.

Description

Most agents shell out to rg, grep and bash. Where those binaries are missing the agent is blind, and where they exist every call is a fork. Mars links the real implementations into the process: search, glob, find and a bash with sessions are in-process, alongside thirty-six built-in tools.

Writes go through the same language servers your editor already runs. A rename calls workspace/willRenameFiles, so re-exports and barrel files follow before the file moves. Debuggers attach over DAP (lldb, dlv, debugpy) instead of print statements.

Flags

What the agent may touch. Each flag is passed or cleared; the consequence prints under it.

--prewalk The first edit hands off to a smaller model.

A one-shot handoff at the first eligible edit or write turn, gated on a successful todo call. --prewalk-into picks a different target than the smol role.

--plan-yolo Plan read-only, then execute unattended.

Starts in read-only plan mode, auto-approves the model's own plan, then switches to the execution target to implement it.

--advisor A second reader watches every turn.

A passive reviewer reads each turn and injects notes; it never takes the turn itself.

--no-lsp Clears language servers, formatting and diagnostics.

Left clear, LSP tools run on every write and renames go through workspace/willRenameFiles, so re-exports and barrel files follow before the file moves.

--auto-approve Force the yolo approval tier.

Explicit tool and user policies still apply, and so do provider safety checks. This raises the ceiling, it does not remove the checks.
